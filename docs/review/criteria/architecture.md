# アーキテクチャ準拠の確認

## 確認項目

### Feature-First アーキテクチャ

- [ ] コードは機能ごとに整理されているか（レイヤーごとではない）
- [ ] 各機能は独立したモジュールとして管理されているか
- [ ] 機能間の依存関係が最小限に抑えられているか

### ディレクトリ構造

- [ ] `lib/features/` 配下に機能が配置されているか
- [ ] 各機能モジュールが以下の構造に従っているか：
  - `{feature}_route.dart`（ルート定義）
  - `presentation/`（UI層）
  - `data/`（データ層、必要に応じて）

### ルーティング

- [ ] ルート定義が `TypedGoRoute` を使用しているか
- [ ] ルートタイプ（`HierarchyRoute` / `ModalRoute`）が適切に選択されているか
- [ ] 全ての画面遷移が `AppNavigator` を経由しているか
- [ ] `BuildContext` に依存せずに遷移を実行しているか

### 状態管理

- [ ] Riverpodを使用しているか
- [ ] `@riverpod` アノテーションを使用しているか
- [ ] ViewModelパターンが適切に実装されているか
- [ ] 状態が不変（immutable）に保たれているか

## 確認方法

### コードレビュー時のチェックポイント

1. **新機能追加時**:
   - 機能が `lib/features/` 配下に配置されているか
   - 機能モジュールの構造が標準に従っているか

2. **画面遷移追加時**:
   - `AppNavigator` を使用しているか
   - `BuildContext` に依存していないか
   - ルートタイプが適切か

3. **状態管理追加時**:
   - Riverpodを使用しているか
   - 状態が不変に保たれているか
   - ViewModelパターンに従っているか

## ベストプラクティス

- アーキテクチャ原則に従っているか
- 既存のパターンと一貫性があるか
- 将来の拡張性を考慮しているか
