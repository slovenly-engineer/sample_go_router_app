# コード品質の確認

## 確認項目

### コーディング規約

- [ ] 命名規則が正しく守られているか
  - ファイル名: スネークケース
  - クラス名: パスカルケース
  - 変数名・関数名: キャメルケース
- [ ] `dart format` でフォーマットされているか
- [ ] `flutter analyze` でエラーがないか

### コード生成

- [ ] ルート定義やRiverpod Providerを変更した場合、コード生成が実行されているか
- [ ] 生成ファイル（`*.g.dart`）が正しく生成されているか
- [ ] 生成ファイルがGitにコミットされているか

### エラーハンドリング

- [ ] エラー状態が適切に管理されているか
- [ ] エラーメッセージがユーザーフレンドリーか
- [ ] 再試行機能が提供されているか（適切な場合）

### テスト

- [ ] 新機能にテストが追加されているか
- [ ] ViewModelのロジックがテストされているか
- [ ] テストカバレッジが適切か

## 確認方法

### 静的解析

```bash
flutter analyze
```

### コードフォーマット

```bash
dart format .
```

### テスト実行

```bash
flutter test
```

## 品質基準

### 必須項目

- 静的解析エラーがない
- テストが通過する
- コードフォーマットが統一されている

### 推奨項目

- テストカバレッジが70%以上
- エラーハンドリングが適切に実装されている
- コメントが適切に記載されている（必要に応じて）

## ベストプラクティス

- コードの可読性を重視する
- 重複コードを避ける
- 適切な抽象化レベルを保つ
