## 1. 機能概要

### 1.1 目的

タスク・TODO管理アプリの中核機能として、ユーザーが日常的にタスクを管理できるホーム画面を提供します。

### 1.2 対象ユーザー

- タスク管理が必要なすべてのユーザー
- 個人のTODOリストを管理したいユーザー
- プロジェクトやカテゴリごとにタスクを整理したいユーザー

### 1.3 主要機能

1. **タスクリスト表示**: タスクを一覧形式で表示
2. **カテゴリ別フィルター**: タブでタスクをフィルタリング（すべて、今日、期限切れ、完了済み）
3. **検索機能**: タスクのタイトルや説明文で検索
4. **タスク操作**: 追加、編集、完了、削除

## 2. ユーザーストーリー

### US-1: タスク一覧表示

**As a** ユーザー
**I want to** タスクの一覧を見る
**So that** 自分が抱えているタスクを把握できる

**受け入れ基準**:
- すべてのタスクがリスト形式で表示される
- 各タスクにはタイトル、期限、完了状態が表示される
- 100+タスクでもスムーズにスクロールできる

### US-2: カテゴリ別フィルター

**As a** ユーザー
**I want to** タスクをカテゴリ別に表示する
**So that** 特定の条件に合うタスクに集中できる

**受け入れ基準**:
- 「すべて」「今日」「期限切れ」「完了済み」の4つのタブが表示される
- タブを切り替えると、該当するタスクのみが表示される
- タブ切り替えは即座に反映される（レスポンシブ）

### US-3: タスク検索

**As a** ユーザー
**I want to** タスクを検索する
**So that** 特定のタスクを素早く見つけられる

**受け入れ基準**:
- AppBarに検索ボタンが表示される
- 検索クエリに部分一致するタスクが表示される
- タイトルと説明文の両方が検索対象となる

### US-4: タスク追加

**As a** ユーザー
**I want to** 新しいタスクを追加する
**So that** やるべきことをリストに記録できる

**受け入れ基準**:
- FloatingActionButtonで追加ダイアログが開く
- タイトル、説明、期限を入力できる
- 保存すると即座にリストに表示される

### US-5: タスク完了

**As a** ユーザー
**I want to** タスクを完了としてマークする
**So that** 完了したタスクと未完了のタスクを区別できる

**受け入れ基準**:
- チェックボックスをタップするとタスクが完了状態になる
- 完了したタスクは「完了済み」タブに表示される
- 完了/未完了の切り替えはトグルで行える

### US-6: タスク削除

**As a** ユーザー
**I want to** 不要なタスクを削除する
**So that** リストを整理できる

**受け入れ基準**:
- タスクアイテムのメニューから削除できる
- 削除前に確認ダイアログが表示される
- 削除すると即座にリストから消える

## 3. 機能要件

### 3.1 タスクリスト表示

| 項目 | 詳細 |
|------|------|
| **表示形式** | 垂直スクロール可能なリスト |
| **ソート順** | 詳細は下記「ソート仕様」を参照 |
| **表示項目** | タイトル、期限、完了状態、メニューボタン |
| **パフォーマンス** | 100+タスクでも60FPSを維持 |

#### ソート仕様

タスクリストは以下の優先順位でソートされます：

1. **完了状態**: 未完了タスクを先に表示、完了タスクを後に表示
2. **期限の有無と日付**:
   - 未完了タスク: 期限あり（期限が近い順）→ 期限なし
   - 完了タスク: 完了日時順（新しい順）
3. **同一条件の場合**: 更新日時順（古い順）

**詳細ルール**:

| タスクの種類 | ソート基準 | 表示タブ |
|-------------|-----------|---------|
| **期限切れ（未完了）** | 期限が古い順 → 更新日時が古い順 | すべて、期限切れ |
| **期限あり（未完了）** | 期限が近い順 → 更新日時が古い順 | すべて、今日（該当する場合） |
| **期限なし（未完了）** | 更新日時が古い順 | すべて |
| **完了済み** | 完了日時が新しい順 | すべて、完了済み |

**期限なしタスクの扱い**:
- 「すべて」タブでのみ表示される
- 「今日」「期限切れ」タブには表示されない

### 3.2 カテゴリ別フィルター

#### フィルター定義

| フィルター名 | 条件 | 説明 |
|--------------|------|------|
| **すべて** | - | すべてのタスクを表示（期限なしタスクも含む） |
| **今日** | `dueDate == 今日の日付` | 今日が期限のタスクを表示（期限なしタスクは非表示） |
| **期限切れ** | `dueDate < 今日 && !isCompleted` | 期限を過ぎた未完了タスクを表示（期限なしタスクは非表示） |
| **完了済み** | `isCompleted == true` | 完了したタスクを表示（期限の有無に関わらず） |

#### UI仕様

- TabBarで4つのタブを表示
- 選択されたタブは下線とテキスト色で強調
- タブ切り替え時はアニメーション付きで遷移

### 3.3 検索機能

| 項目 | 詳細 |
|------|------|
| **検索対象** | タスクのタイトルと説明文 |
| **検索方法** | 部分一致（大文字小文字を区別しない） |
| **UI** | AppBarの検索アイコンをタップで検索フィールド表示 |
| **リアルタイム更新** | 検索クエリの入力に応じてリストが即座に更新される |

### 3.4 タスクCRUD操作

#### 作成（Create）

- FloatingActionButtonをタップ
- ダイアログで以下を入力:
  - タイトル（必須）
  - 説明（任意）
  - 期限（任意）
- 保存すると即座にリストに反映

#### 読み取り（Read）

- アプリ起動時に自動読み込み
- ローカルストレージ（SharedPreferences）から取得
- エラー時は再試行ボタンを表示

#### 更新（Update）

- タスク完了: チェックボックスのトグル
- タスク編集: タスクアイテムタップで編集ダイアログ表示
- 変更は即座に保存される

#### 削除（Delete）

- タスクアイテムのメニューから「削除」を選択
- 確認ダイアログで「削除」を確認
- 削除は取り消し不可（将来的にはundo機能を検討）

## 4. 非機能要件

### 4.1 パフォーマンス

| 項目 | 目標値 |
|------|--------|
| **初期表示** | 1秒以内 |
| **タブ切り替え** | 0.3秒以内 |
| **検索結果表示** | リアルタイム（入力に追従） |
| **スクロール** | 100+タスクで60FPS維持 |

### 4.2 ユーザビリティ

- **直感的な操作**: チェックボックスでタスク完了、FABで追加
- **視覚的フィードバック**: アニメーション、色の変化
- **エラーハンドリング**: わかりやすいエラーメッセージ
- **空状態**: タスクが0件の時は「タスクがありません」メッセージ

### 4.3 アクセシビリティ

- すべてのインタラクティブ要素にセマンティクスラベルを設定
- 十分なタップ領域（44x44pt以上）
- コントラスト比を確保（WCAG 2.1 AAレベル準拠）

### 4.4 保守性

- Feature-First Architectureに準拠
- ユニットテストカバレッジ80%以上
- コード重複を最小化（DRY原則）

## 5. データ仕様

### 5.1 TaskModel

```dart
class TaskModel {
  /// タスクの一意識別子（UUID v4）
  final String id;

  /// タスクのタイトル（必須、最大200文字）
  final String title;

  /// タスクの説明（任意、最大1000文字）
  final String? description;

  /// タスクの期限（任意）
  final DateTime? dueDate;

  /// タスクの完了状態
  final bool isCompleted;

  /// タスクの完了日時（任意、完了時に設定）
  final DateTime? completedAt;

  /// タスクの作成日時
  final DateTime createdAt;

  /// タスクの最終更新日時
  final DateTime updatedAt;

  const TaskModel({
    required this.id,
    required this.title,
    this.description,
    this.dueDate,
    required this.isCompleted,
    this.completedAt,
    required this.createdAt,
    required this.updatedAt,
  });
}
```

### 5.2 HomeState

```dart
class HomeState {
  /// タスクリスト
  final List<TaskModel> tasks;

  /// 選択中のフィルター
  final TaskFilter selectedFilter;

  /// 検索クエリ
  final String searchQuery;

  /// ローディング状態
  final bool isLoading;

  /// エラーメッセージ
  final String? error;

  const HomeState({
    required this.tasks,
    required this.selectedFilter,
    this.searchQuery = '',
    this.isLoading = false,
    this.error,
  });
}

enum TaskFilter {
  all,      // すべて
  today,    // 今日
  overdue,  // 期限切れ
  completed // 完了済み
}
```

### 5.3 データ永続化

| 項目 | 詳細 |
|------|------|
| **ストレージ** | SharedPreferences（初期実装） |
| **キー** | `tasks_data` |
| **形式** | JSON配列 |
| **最大サイズ** | 制限なし（実用上は1000タスク程度を想定） |

**将来の拡張**:
- Hive: より高速なパフォーマンスが必要な場合
- API連携: バックエンドサーバーとの同期が必要な場合

### 7.2 統合テスト

#### シナリオ1: タスク追加フロー

1. FABをタップ
2. ダイアログが表示される
3. タイトル「買い物に行く」を入力
4. 期限を「今日」に設定
5. 保存をタップ
6. タスクリストに「買い物に行く」が表示される
7. 「今日」タブに切り替え
8. 「買い物に行く」が表示される

#### シナリオ2: タスク完了フロー

1. 「すべて」タブで未完了タスクを表示
2. タスクのチェックボックスをタップ
3. タスクが完了状態になる
4. 「完了済み」タブに切り替え
5. 完了したタスクが表示される

#### シナリオ3: 検索フロー

1. 検索アイコンをタップ
2. 検索フィールドが表示される
3. 「買い物」と入力
4. 「買い物」を含むタスクのみが表示される
5. 検索クエリをクリア
6. すべてのタスクが再度表示される

#### シナリオ4: フィルタリングフロー

1. 複数のタスクを追加（期限: 今日、明日、過去、未設定）
2. 「今日」タブに切り替え
3. 期限が今日のタスクのみが表示される
4. 「期限切れ」タブに切り替え
5. 期限が過去の未完了タスクのみが表示される
6. 「完了済み」タブに切り替え
7. 完了したタスクのみが表示される

#### シナリオ5: ソート順の確認フロー

1. 複数のタスクを追加:
   - タスクA: 期限切れ（3日前）、更新日時: 昨日
   - タスクB: 期限切れ（2日前）、更新日時: 今日
   - タスクC: 今日期限、更新日時: 2日前
   - タスクD: 明日期限、更新日時: 今日
   - タスクE: 期限なし、更新日時: 3日前
2. 「すべて」タブで表示順を確認:
   - 期限切れ: A（古い期限） → B（新しい期限）
   - 今日: C
   - 明日: D
   - 期限なし: E
3. タスクCを完了する
4. 「すべて」タブで表示順を確認:
   - タスクCが一番下に移動している
5. 「完了済み」タブで確認:
   - タスクCが表示されている

## 8. 制約事項

### 8.1 技術的制約

- Flutter 3.x以上が必要
- iOS 12.0以上、Android 5.0以上をサポート
- ローカルストレージのみ（オフラインファースト）

### 8.2 ビジネス的制約

- フェーズ1では基本的なCRUD操作のみを実装
- カテゴリ・プロジェクト機能は将来のフェーズで実装
- リマインダー・通知機能は将来のフェーズで実装
