# アーキテクチャ決定記録 (ADR)

このディレクトリには、プロジェクトで行われた重要な技術的決定とその理由を記録します。

## ADRとは

ADR (Architecture Decision Records) は、重要な技術的決定を文書化するための方法です。各決定について、以下の情報を記録します：

- **背景**: なぜその決定が必要だったか
- **決定**: 何を決定したか
- **理由**: なぜその選択をしたか
- **代替案**: 検討した他の選択肢
- **影響**: その決定による影響

## ADRの命名規則

ADRファイルは以下の形式で命名します：

```
ADR-{番号}-{簡潔なタイトル}.md
```

例: `ADR-001-feature-first-architecture.md`

## ADRテンプレート

新しいADRを作成する際は、以下のテンプレートを使用してください：

```markdown
# ADR-{番号}: {タイトル}

## ステータス

提案中 / 承認済み / 却下 / 非推奨

## 背景

なぜこの決定が必要だったかを説明します。

## 決定

何を決定したかを明確に記述します。

## 理由

なぜこの選択をしたかを説明します。

## 代替案

検討した他の選択肢と、それらを選ばなかった理由を説明します。

## 影響

この決定による影響（メリット・デメリット）を説明します。

## 関連ADR

関連する他のADRへのリンク。
```

## ADRを作成すべきタイミング

以下のような場合にADRを作成することを推奨します：

- アーキテクチャパターンの選択（例: Feature-First vs Layer-First）
- 主要なライブラリの選択（例: Riverpod vs Provider）
- ナビゲーション戦略の決定（例: AppNavigatorパターン）
- 状態管理アプローチの選択
- テスト戦略の決定
- その他、将来の判断に影響を与える重要な技術的決定
